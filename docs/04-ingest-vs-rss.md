# 04 — 为什么用 RSS，而不是 POST ingest

## 问题

AIHOT / XRHOT 的 `POST /api/ingest/items` **可以**接收外部条目，但接口语义是「有这么一篇文章」：

- 收：`title`、`url`、`publishedAt`、`author`
- **不收正文**；正文由站内 worker 打开原网页抓取

对普通网站文章：可行。  
对 **X 帖子**：服务器打开 `x.com` → 登录墙或空页 → 你在浏览器里已取到的原文**用不上**。  
框架里 X 正文原本走 SocialData / `x_search`，与「外部已取原文」接不上。

上游 AIHOT（核对日约 cf1c464）推送接口同样只收上述字段。

## 决定

使用 **公网 RSS**：

- `content:encoded` 内放帖子**全文**（逐字）
- 站定时拉取（最快约 15 分钟一级）
- 不必把 ingest 口令交给采集 agent
- 更安全、可抽查与原帖逐字核对

## 站内必要开关

打开：**短帖也算正文**。  
否则约 280 字以下可能被当成摘要而非正文。

## 不要做的退路

- 不要为了「推正文」去改站代码（那是站仓职责；本仓只保证 RSS 合格）
- 不要让服务器再去抓 x.com
- 不要订 SocialData 仅为此任务（除非产品另有决策并写入 ADR）
